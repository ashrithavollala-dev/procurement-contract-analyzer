# API Contract (single source of truth)

Base path: `/api/v1`. All bodies are JSON (`application/json`) unless stated otherwise.
Timestamps are ISO-8601 UTC strings (`2026-10-13T09:15:30.123Z`). Contract and audit ids are
UUID strings; rule and finding ids are numbers. Enums are serialized as the raw uppercase
string; the frontend maps them to friendly labels. The OpenAPI document generated by
springdoc (`/v3/api-docs`, UI at `/swagger-ui.html`) describes the same endpoints.

## Enums

| Enum | Values |
|---|---|
| `ContractStatus` | `UPLOADED`, `QUEUED`, `PROCESSING`, `READY`, `FAILED` |
| `AuditStatus` | `QUEUED`, `RUNNING`, `COMPLETED`, `FAILED` |
| `FindingStatus` | `COMPLIANT`, `PARTIAL`, `NON_COMPLIANT`, `NOT_FOUND`, `NEEDS_REVIEW` |
| `Severity` | `LOW`, `MEDIUM`, `HIGH`, `CRITICAL` |
| `RiskBand` | `LOW`, `MEDIUM`, `HIGH`, `CRITICAL` |
| `LlmProvider` (system status) | `ollama`, `openai` (lowercase, as configured) |
| `QaMode` | `rag`, `tools` (lowercase, as configured) |

## Error payload (every non-2xx response)

```json
{
  "timestamp": "2026-10-13T09:15:30.123Z",
  "status": 400,
  "error": "Bad Request",
  "code": "VALIDATION_FAILED",
  "message": "Request validation failed",
  "path": "/api/v1/search",
  "details": { "query": "must not be blank", "topK": "must be less than or equal to 20" }
}
```

`details` is optional: a `fieldName -> message` map for validation errors, or a small map of
context values (e.g. `existingContractId`, `contractId`). Clients branch on `code` and
`status`, never on `message`.

| Code | HTTP | Meaning |
|---|---|---|
| `RESOURCE_NOT_FOUND` | 404 | Contract, audit or rule id does not exist |
| `VALIDATION_FAILED` | 400 (409 for a duplicate rule code) | Bean Validation or business validation failed; `details` per field |
| `UNSUPPORTED_FILE_TYPE` | 415 | Not a PDF (magic bytes `%PDF-` / content type), or unreadable/encrypted PDF |
| `FILE_TOO_LARGE` | 413 | Upload exceeds the configured size limit |
| `DUPLICATE_CONTRACT` | 409 | Same SHA-256 content already uploaded; `details.existingContractId` |
| `CONTRACT_NOT_READY` | 409 | The contract's status does not allow the operation (audit/ask need `READY`; reprocess needs `FAILED` or `READY`+`force`; delete is refused while `QUEUED`/`PROCESSING`) |
| `NO_ACTIVE_RULES` | 409 | Audit requested without ruleCodes and no rule is active |
| `NO_EXTRACTABLE_TEXT` | — | Stored on a FAILED contract (`errorCode`), not returned as an HTTP error |
| `INGESTION_QUEUE_FULL` | 503 | Ingestion executor queue is full; the contract was stored as FAILED; `details.contractId` |
| `AUDIT_QUEUE_FULL` | 503 | Audit executor queue is full; the run was stored as FAILED; `details.auditId` (addition to the original list) |
| `INTERRUPTED` | — | Stored on a contract/audit that was in flight when the backend stopped |
| `LLM_UNAVAILABLE` | 503 | Chat model unreachable or not configured |
| `LLM_TIMEOUT` | 504 | Chat model call exceeded its timeout |
| `LLM_OUTPUT_INVALID` | — | Stored on a finding whose structured output failed validation twice |
| `INTERNAL_ERROR` | 500 | Unexpected error (details never contain stack traces) |

## Pagination

```json
{ "content": [ ... ], "page": 0, "size": 20, "totalElements": 42, "totalPages": 3 }
```
Query parameters `page` (0-based, default 0) and `size` (1..100, default 20).

## Contracts

### Contract object (`ContractResponse`)

```json
{
  "id": "6f1c1f9e-2c7a-4b5e-9d55-0d8e4a2c1b11",
  "title": "Master Services Agreement - Northwind Logistics",
  "vendorName": "Northwind Logistics Ltd (fictional)",
  "originalFilename": "contract-wellformed.pdf",
  "contentHash": "3a7bd3e2360a3d29eea436fcfb7e44c735d117c42d1c1835420b6b9942dd4f1b",
  "fileSizeBytes": 18234,
  "pageCount": 4,
  "chunkCount": 21,
  "status": "READY",
  "errorCode": null,
  "errorMessage": null,
  "processedAt": "2026-10-13T09:16:02.511Z",
  "createdAt": "2026-10-13T09:15:30.123Z",
  "updatedAt": "2026-10-13T09:16:02.511Z"
}
```
`pageCount` and `chunkCount` are `null` until processing completes.

### POST /contracts → 202 Accepted
`multipart/form-data`: `file` (required, PDF), `title` (optional, max 255; defaults to the
file name without extension), `vendorName` (optional, max 255).
Response: the contract (status `QUEUED`), header `Location: /api/v1/contracts/{id}`.
Errors: 400 `VALIDATION_FAILED` (missing/empty file, too many pages, field lengths),
413 `FILE_TOO_LARGE`, 415 `UNSUPPORTED_FILE_TYPE`, 409 `DUPLICATE_CONTRACT`
(`details: { "existingContractId": "..." }`), 503 `INGESTION_QUEUE_FULL`
(`details: { "contractId": "..." }`).

### GET /contracts?status=READY&q=northwind&page=0&size=20 → 200
`status` optional `ContractStatus`; `q` optional, case-insensitive match on title, vendor
name or original filename. Sorted by `createdAt` descending.
Response: `PageResponse<ContractResponse>`. Errors: 400 `VALIDATION_FAILED` (bad enum, page/size).

### GET /contracts/{id} → 200 `ContractResponse`
Errors: 404 `RESOURCE_NOT_FOUND`, 400 `VALIDATION_FAILED` (id not a UUID).

### GET /contracts/{id}/file → 200 `application/pdf`
Header `Content-Disposition: attachment; filename="<originalFilename>"`. Errors: 404.

### POST /contracts/{id}/reprocess?force=false → 202 `ContractResponse` (status `QUEUED`)
Allowed from `FAILED`, or from `READY` when `force=true`. Idempotent: existing vectors are
deleted first and vector ids are deterministic. Errors: 404, 409 `CONTRACT_NOT_READY`,
503 `INGESTION_QUEUE_FULL`.

### DELETE /contracts/{id} → 204 No Content
Deletes vectors, the stored file and the rows (audit runs and findings cascade).
Errors: 404, 409 `CONTRACT_NOT_READY` (while `QUEUED`/`PROCESSING`), 500 `INTERNAL_ERROR`
if vector deletion fails (rows are kept so the delete can be retried).

## Semantic search

### POST /search → 200
Request:
```json
{ "query": "limitation of liability cap", "contractId": null, "topK": 5, "minScore": 0.3 }
```
`query` required, 2..1000 chars; `contractId` optional UUID; `topK` optional 1..20
(default 5); `minScore` optional 0..1 (default `app.search.default-min-score`, 0.0).
Response:
```json
{
  "query": "limitation of liability cap",
  "results": [
    {
      "contractId": "6f1c1f9e-2c7a-4b5e-9d55-0d8e4a2c1b11",
      "contractTitle": "Master Services Agreement - Northwind Logistics",
      "page": 3,
      "chunkIndex": 12,
      "heading": "ARTICLE 9 LIMITATION OF LIABILITY",
      "snippet": "9.1 The aggregate liability of either Party ... shall not exceed ...",
      "score": 0.7134
    }
  ]
}
```
Works without an LLM. Errors: 400 `VALIDATION_FAILED`, 404 when `contractId` is unknown.

## Audits

### POST /contracts/{id}/audits → 202
Request (body optional): `{ "ruleCodes": ["LIABILITY_CAP", "AUDIT_RIGHTS", "DATA_PROTECTION"] }`.
`null`/absent/empty → all active rules. Every code must exist (inactive codes may be
requested explicitly). Response: `{ "auditId": "b0c...", "status": "QUEUED" }`.
Errors: 404, 400 `VALIDATION_FAILED` (`details.ruleCodes` lists unknown codes),
409 `CONTRACT_NOT_READY`, 409 `NO_ACTIVE_RULES`, 503 `LLM_UNAVAILABLE`, 503 `AUDIT_QUEUE_FULL`.

### Audit run summary (`AuditRunSummaryResponse`)
```json
{
  "id": "b0c4e9a2-1d2f-4c55-8e61-2f0b6a9d3c77",
  "contractId": "6f1c1f9e-2c7a-4b5e-9d55-0d8e4a2c1b11",
  "contractTitle": "Master Services Agreement - Northwind Logistics",
  "status": "COMPLETED",
  "totalRules": 3,
  "completedRules": 3,
  "riskScore": 33.3,
  "riskBand": "MEDIUM",
  "summary": "3 rules evaluated: 2 compliant, 0 partial, 1 non-compliant, 0 not found, 0 need review.",
  "errorCode": null,
  "startedAt": "2026-10-13T09:20:00.000Z",
  "completedAt": "2026-10-13T09:22:41.000Z",
  "createdAt": "2026-10-13T09:19:59.000Z"
}
```
`riskScore`/`riskBand` are `null` until `COMPLETED`.

### GET /contracts/{id}/audits → 200 `AuditRunSummaryResponse[]` (newest first). Errors: 404.

### GET /audits/{auditId} → 200 `AuditRunDetailResponse`
All summary fields plus `findings`:

## Q&A

### POST /contracts/{id}/ask → 200
Request: `{ "question": "What is the notice period for termination for convenience?" }`
(`question` required, 3..1000 chars).
Response:
```json
{
  "answer": "Either party may terminate for convenience with sixty (60) days' written notice.",
  "grounded": true,
  "mode": "rag",
  "citations": [
    { "page": 2, "chunkIndex": 7, "snippet": "11.2 Either Party may terminate this Agreement for convenience ...", "score": 0.6821 }
  ]
}
```
`grounded=false` (with empty `citations`) when nothing relevant was retrieved; `answer` then
states that the information cannot be found in the contract. Citations come from the chunks
the server retrieved, never from model text. Errors: 404, 400, 409 `CONTRACT_NOT_READY`,
503 `LLM_UNAVAILABLE`, 504 `LLM_TIMEOUT`.

## Compliance rules

### Rule object (`RuleResponse`)
```json
{
  "id": 3,
  "code": "LIABILITY_CAP",
  "title": "Limitation of liability cap",
  "question": "Does the contract cap the supplier's total aggregate liability ...?",
  "guidance": "Compliant: an explicit monetary or fee-based cap ...",
  "severity": "CRITICAL",
  "mandatory": true,
  "active": true,
  "createdAt": "2026-10-13T09:00:00.000Z",
  "updatedAt": "2026-10-13T09:00:00.000Z"
}
```

### GET /compliance-rules?activeOnly=false → 200 `RuleResponse[]` (ordered by code)

### POST /compliance-rules → 201 `RuleResponse` (header `Location`)
```json
{ "code": "WARRANTY_PERIOD", "title": "Warranty period", "question": "...", "guidance": "...",
  "severity": "MEDIUM", "mandatory": false, "active": true }
```
`code` required, pattern `^[A-Z][A-Z0-9_]{2,63}$`; `title` 3..200; `question` 10..2000;
`guidance` 10..4000; `severity` required; `mandatory` required; `active` optional (default true).
Errors: 400 `VALIDATION_FAILED`, 409 `VALIDATION_FAILED` (`details.code`: already exists).

### PUT /compliance-rules/{id} → 200 `RuleResponse`
Same body without `code` (codes are immutable); `active` required. Errors: 404, 400.

### PATCH /compliance-rules/{id}/active → 200 `RuleResponse`
`{ "active": false }` (`active` required). Errors: 404, 400.

## Dashboard

### GET /dashboard/summary → 200
```json
{
  "totalContracts": 3,
  "contractsByStatus": { "UPLOADED": 0, "QUEUED": 0, "PROCESSING": 0, "READY": 2, "FAILED": 1 },
  "totalAudits": 2,
  "averageRiskScore": 41.7,

  "topNonCompliantRules": [
    { "ruleCode": "LIABILITY_CAP", "ruleTitle": "Limitation of liability cap", "severity": "CRITICAL", "count": 1 }
```

findings with status `NON_COMPLIANT` or `NOT_FOUND` (max 5).

## System

### GET /system/status → 200
```json
{
  "llmProvider": "ollama",
  "llmModel": "llama3.2:3b",
  "llmReachable": true,
  "llmDetail": "Ollama reachable at http://localhost:11434",
  "qaMode": "rag",
  "embeddingModel": "sentence-transformers/all-MiniLM-L6-v2 (ONNX)",
  "embeddingDimension": 384,
  "checkedAt": "2026-10-13T09:15:30.123Z"
}
```
Reachability is probed and cached for `app.llm.status-cache-ttl` (default 15 s). For Ollama
the probe is `GET {base-url}/api/tags` with a 3 s timeout, and it also requires that the
configured model is pulled. For OpenAI it checks that a key is configured. `llmDetail` is a
short human-readable reason (never contains secrets).
